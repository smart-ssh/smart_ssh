# Spec: Erststart-Hinweis (Verantwortung & Datenbank-Verschlüsselung)

Status: Entwurf
Modul: `crates/app-tauri` (Erststart-Erkennung), `frontend/` (Zustimmungs-
Screen)
Abhängigkeiten: Einstellungs-Speicher (Spec 0024, `tauri-plugin-store`),
i18n (Spec 0024), bereits offener Hinweis-Punkt aus Spec 0004, Abschnitt 7

## 1. Ziel

Beim allerersten App-Start, bevor eine erste Server-Verbindung aufgebaut
werden kann, zeigt die App einen Zustimmungs-Screen mit zwei inhaltlichen
Punkten in einem Rutsch:

1. **Verantwortung**: Die KI schlägt Kommandos vor, aber der Nutzer trägt
   die Verantwortung für jedes bestätigte Kommando; keine Haftung des
   Herstellers für Schäden durch ausgeführte Kommandos.
2. **Datenbank-Verschlüsselung**: Die lokale SQLite-Datenbank ist nicht
   zusätzlich verschlüsselt (Spec 0004, Abschnitt 7), OS-Festplatten-
   verschlüsselung wird empfohlen.

Beide Punkte in einem gemeinsamen Screen statt zwei getrennter Popups
nacheinander — vermeidet, dass der Nutzer zwei ähnliche Dialoge
wegklicken muss, bevor er die App nutzen kann.

## 2. Anzeigebedingung

Der Screen erscheint **einmalig**, vor dem ersten Server-Verbindungsaufbau,
danach nie wieder — außer der Nutzer setzt die Einstellung explizit zurück
(kein UI dafür in dieser Spec vorgesehen, nur bewusst nicht ausgeschlossen
für später). Zustand wird über `tauri-plugin-store` gespeichert
(`first_run_notice_acknowledged: bool`, Default `false`), analog zum Muster
aus Spec 0024 für die Sprachauswahl — keine SQLite-Migration dafür.

## 3. Inhalt (Deutsch/Englisch, i18n-Keys gemäß Spec 0024)

**Deutsch:**

```
Bevor es losgeht

Smart SSH schlägt dir Kommandos vor, die eine KI basierend auf deinen
Anfragen generiert. Nichts wird ausgeführt, ohne dass du es bestätigst —
außer du hast das über eigene Regeln bewusst anders eingestellt. Die
Verantwortung für jedes bestätigte Kommando liegt bei dir.

Die lokale Datenbank ist nicht zusätzlich verschlüsselt. Wir empfehlen, die
Festplattenverschlüsselung deines Betriebssystems zu aktivieren, falls noch
nicht geschehen.

[ ] Ich habe das gelesen und verstanden.
              [Weiter]
```

**Englisch:**

```
Before you start

Smart SSH proposes commands generated by an AI based on your requests.
Nothing runs without your confirmation — unless you've explicitly set up a
rule that allows it. You're responsible for every command you approve.

The local database is not separately encrypted. We recommend enabling your
operating system's disk encryption if you haven't already.

[ ] I've read and understood this.
              [Continue]
```

## 4. Verhalten

- "Weiter"-Button bleibt deaktiviert, bis die Checkbox aktiv ist — reines
  Wegklicken ohne bewusste Bestätigung soll nicht möglich sein.
- Nach Bestätigung: `first_run_notice_acknowledged` wird auf `true`
  gesetzt, der Screen erscheint bei künftigen Starts nicht mehr.
- Der Screen blockiert **nur** den ersten Server-Verbindungsaufbau, nicht
  die übrige App-Nutzung (z. B. Provider-Einstellungen konfigurieren bleibt
  vorher möglich) — er muss also nicht zwingend der allererste Bildschirm
  nach dem App-Start sein, aber vor `connect()` muss er bestätigt sein.

## 5. Offene Punkte

- Kein UI zum nachträglichen erneuten Anzeigen des Hinweises (z. B. über
  "Rechtliches" in den Einstellungen) — naheliegende kleine Ergänzung,
  nicht Teil dieser Spec.
